# 🔐 asc wireguard

WireGuard ноды: создание туннелей, пиры со сгенерированными ключами и готовым
клиентским конфигом, выбор того, до чего пир может достучаться (AllowedIPs),
включение и выключение туннелей, просмотр их конфигурации и импорт готового
`.conf`. Как записываются файлы — на странице модуля
[🔐 WireGuard](/ru/cli/wireguard).

## Использование

```
asc wireguard <действие> [аргументы]
```

WireGuard управляется от root — запускайте команды через `sudo`. Они обращаются
к работающему демону; сначала запустите его: `sudo asc service start`.

### status

```
asc wireguard status
```

Показывает версию, собственный адрес ноды и каждый туннель: поднят или нет,
запускается ли при загрузке, порт, адреса, NAT, команды, которые он выполняет
от root, и его пиров с последним рукопожатием и трафиком каждого. Файлы в
`/etc/wireguard`, которыми ASC не управляет, перечислены ниже.

### install

```
asc wireguard install
```

Устанавливает `wireguard-tools` (apt или dnf). Вывод идёт потоком.

### uninstall

```
asc wireguard uninstall [--purge]
```

Останавливает туннели под управлением демона и удаляет пакет. **`--purge`**
дополнительно удаляет их файлы конфигурации, в которых лежат приватные ключи.

### add

```
asc wireguard add <имя> --address <cidr>... [--port <порт>] [--dns <адрес>]... [--mtu <n>] [--endpoint <хост>] [--nat]
```

Создаёт туннель с новым ключом и поднимает его сейчас и при загрузке.

- **`--address`** — адрес и сеть туннеля, например `10.8.0.1/24`. Можно
  повторять (например, сеть IPv4 и сеть IPv6).
- **`--port`** — UDP-порт (по умолчанию 51820); `0` делает клиентский туннель,
  который не слушает порт.
- **`--dns`** — DNS-сервер, который получают клиенты. Это заметка для
  клиентских конфигов, а не строка `DNS =` на сервере.
- **`--endpoint`** — публичное имя или адрес, к которому подключаются клиенты.
- **`--nat`** — выпустить сеть VPN в интернет через маскарад (IPv4).

```
sudo asc wireguard add wg0 --address 10.8.0.1/24 --endpoint vpn.example.com --nat
```

### set

```
asc wireguard set <имя> [--address <cidr>]... [--port <порт>] [--dns <адрес>]... [--mtu <n>] [--endpoint <хост>] [--nat <bool>]
```

Меняет туннель под управлением демона. Пиры и порт применяются к работающему
туннелю без обрыва; адреса, MTU и NAT пересобирают интерфейс (короткий разрыв).
Изменение, которое WireGuard не принял, откатывается.

### remove

```
asc wireguard remove <имя>
```

Опускает туннель и удаляет его файл.

### up

```
asc wireguard up <имя>
```

Поднимает туннель и включает его при загрузке. Работает и с файлами, которыми
ASC не управляет.

### down

```
asc wireguard down <имя>
```

Опускает туннель и выключает его при загрузке.

### show

```
asc wireguard show <имя>
```

Печатает файл конфигурации туннеля, приватный и pre-shared ключи заменены на
`(hidden)`. Работает и с файлами, которыми ASC не управляет.

### import

```
asc wireguard import <файл|-> [--name <имя>] [--overwrite] [--accept-hooks] [--start]
```

Принимает готовый `.conf` — серверный (с `ListenPort` и пирами) или клиентский
(один пир с `Endpoint`): проверяет, переписывает с меткой ASC и сохраняет
ключи. Имя по умолчанию — имя файла; `-` читает стандартный ввод (тогда
`--name` обязателен).

- **`--overwrite`** — заменить туннель с таким именем; старый файл сохраняется
  как `<имя>.conf.asc-bak`.
- **`--accept-hooks`** — разрешить команды `PreUp`, `PostUp`, `PreDown` и
  `PostDown` из файла. Они выполняются от root, поэтому без этого флага импорт
  отклоняется. `SaveConfig = true` отбрасывается всегда.
- **`--start`** — поднять туннель и включить его при загрузке.

Всё, что отброшено или не понято, печатается предупреждением.

```
sudo asc wireguard import office.conf --start
```

### peer add

```
asc wireguard peer add <интерфейс> <имя> [--public-key <ключ>] [--allowed-ips <cidr>]... [--no-psk] [--keepalive <с>] [--endpoint <хост:порт>] [--routes <full|subnet|список>] [--client-dns <адрес>]... [--client-endpoint <хост>] [-o <файл>]
```

Добавляет пира: следующий свободный адрес сети туннеля, сгенерированная пара
ключей и pre-shared key, клиентский конфиг. В конфиге лежит приватный ключ пира,
и он **показывается только сейчас**; демон хранит только публичный. С
`--output` конфиг записывается в файл, читаемый только владельцем.

- **`--public-key`** — использовать ключ, который клиент создал сам; в конфиге
  будет заглушка `<PRIVATE_KEY>`.
- **`--allowed-ips`** — адреса пира и сети за ним вместо следующего свободного
  адреса.
- **`--routes`** — что клиент отправляет в туннель (его AllowedIPs): `full`
  (`0.0.0.0/0, ::/0`), `subnet` (только сеть VPN, по умолчанию) или список
  вроде `10.8.0.0/24,192.168.10.0/24`.
- **`--client-dns`**, **`--client-endpoint`** — заменить DNS или публичный хост
  туннеля в этом конфиге.
- **`--keepalive`** — секунды между keepalive (по умолчанию 25); `0` — выкл.
- **`--no-psk`** — без pre-shared key.

```
sudo asc wireguard peer add wg0 phone --routes full -o phone.conf
```

### peer set

```
asc wireguard peer set <интерфейс> <пир> [--name <имя>] [--allowed-ips <cidr>]... [--endpoint <хост:порт>] [--keepalive <с>] [--enable | --disable]
```

Меняет пира; `<пир>` — его публичный ключ или имя. **`--allowed-ips`** заменяет
адреса и сети, маршрутизируемые на него, — добавьте сеть за пиром для
site-to-site. **`--disable`** оставляет пира в файле, но отключает его;
**`--enable`** загружает снова.

```
sudo asc wireguard peer set wg0 phone --allowed-ips 10.8.0.2/32,192.168.50.0/24
```

### peer remove

```
asc wireguard peer remove <интерфейс> <пир>
```

Удаляет пира.

### peer config

```
asc wireguard peer config <интерфейс> <пир> [--routes <full|subnet|список>] [--client-dns <адрес>]... [--client-endpoint <хост>] [-o <файл>]
```

Печатает клиентский конфиг существующего пира. Демон не хранит приватный ключ
пира, поэтому в файле стоит заглушка `<PRIVATE_KEY>`. Параметры те же, что у
`peer add`.
