# 🛡️ asc firewall

Файрвол ноды: правила nftables в одной таблице, которой владеет демон
(`inet asc`), списки разрешённых и заблокированных адресов и экспертный режим,
в котором правится весь ruleset. Любое изменение применяется с **автоматическим
откатом** — если вы не подтвердили его вовремя, возвращаются прежние правила.
Как рендерятся правила и как работает откат — на странице модуля
[🛡️ firewall](/ru/cli/firewall).

## Использование

```
asc firewall <действие> [аргументы]
```

Файрволом управляет root — запускайте команды через `sudo`. Они обращаются к
работающему демону (таймер отката живёт в нём); сначала запустите его:
`sudo asc service start`.

В терминале изменение, которое ждёт подтверждения, спрашивает `Оставить новые
правила? [Y/n]` с обратным отсчётом. Без терминала команда напечатает, как
подтвердить, и оставит таймер работать.

### status

```
asc firewall status
```

Показывает режим, политику входящих, настройки, изменение, ожидающее
подтверждения, конкурирующий ufw/firewalld, неприменённые изменения и правила
(в том числе выведенные из хоста) со счётчиками пакетов.

### install

```
asc firewall install
```

Устанавливает пакет `nftables`.

### enable

```
asc firewall enable [--timeout <секунды>] [--no-rollback] [--force] [--no-wait]
```

Включает управляемый файрвол: загружает `table inet asc` из сохранённых правил с
политикой входящих (по умолчанию `drop`). Порт SSH, порт API демона и — если
установлен веб-сервер — порты 80 и 443 открываются автоматически, так что
включение не отрежет вам доступ.

- **`--timeout <секунды>`** — окно подтверждения, 15–600 (по умолчанию 60).
- **`--no-rollback`** — зафиксировать сразу, без окна (для скриптов).
- **`--force`** — выключить конкурирующий ufw или firewalld; без флага команда
  отказывает, пока тот активен.
- **`--no-wait`** — не ждать ответа на запрос подтверждения.

```
sudo asc firewall enable
```

### disable

```
asc firewall disable
```

Удаляет `table inet asc` и юнит автозагрузки. Изменение, ожидающее
подтверждения, нужно сначала подтвердить или откатить.

### allow

```
asc firewall allow [<порты>[/tcp|/udp] | icmp] [--from <адрес>]... [флаги...]
```

Добавляет разрешающее правило. Порты без протокола — это TCP. При включённом
файрволе правило применяется сразу, с окном подтверждения; при выключенном —
только сохраняется.

- **`<порты>`** — `443`, `80,443/tcp`, `8000-8100/udp`; `icmp` для правил про ping.
- **`--from <адрес>`** — только для этого источника: IP, CIDR, `@allowlist` или
  `@blocklist`. Можно повторять.
- **`--scope host|docker|both`** — трафик к этой машине, к портам, которые
  публикует Docker, или оба (по умолчанию `host`).
- **`--comment <текст>`**, **`--id <id>`** — заметка и фиксированный id.
- **`--no-apply`** — сохранить правило, не применяя.
- **`--timeout <секунды>`** — окно подтверждения.

```
sudo asc firewall allow 443/tcp
sudo asc firewall allow 5432/tcp --from 10.0.0.0/8 --comment "postgres, частная сеть"
```

### deny

```
asc firewall deny [<порты>[/tcp|/udp] | icmp] [--from <адрес>]... [--reject] [флаги...]
```

Добавляет правило, которое отбрасывает подходящий трафик. Запреты проверяются
раньше разрешений, поэтому порядок в списке не важен. **`--reject`** отвечает
сбросом соединения или ICMP-ошибкой вместо молчаливого отбрасывания. Остальные
флаги — как у `allow`.

```
sudo asc firewall deny --from 203.0.113.7
sudo asc firewall deny 8080/tcp --scope docker --from 203.0.113.0/24
```

### rules

```
asc firewall rules
```

Список правил: id, действие, состояние, протокол, порты, источники, scope,
счётчик пакетов и комментарий. Правила, выведенные из хоста, называются
`preset-ssh`, `preset-api` и `preset-web`.

### remove

```
asc firewall remove <id> [--no-apply] [--timeout <секунды>]
```

Удаляет правило.

### set list

```
asc firewall set list [allowlist|blocklist]
```

Показывает записи allowlist и blocklist со сроком действия.

### set add

```
asc firewall set add <allowlist|blocklist> <адрес> [--ttl <срок>] [--comment <текст>] [--no-apply] [--timeout <секунды>]
```

Добавляет IP или CIDR. Блоклист сильнее любых правил и защищает также
опубликованные порты Docker; аллоулист пропускается раньше правил. **`--ttl`**
(`90s`, `30m`, `24h`, `7d`) убирает запись через указанное время.

```
sudo asc firewall set add blocklist 203.0.113.7 --ttl 24h --comment сканер
```

### set remove

```
asc firewall set remove <allowlist|blocklist> <адрес> [--no-apply] [--timeout <секунды>]
```

Убирает адрес или сеть из набора.

### settings

```
asc firewall settings [--policy accept|drop] [--icmp <bool>] [--ipv6 <bool>] [--protect-docker <bool>] [--disable-preset <имя>]... [--enable-preset <имя>]... [--force]
```

Меняет настройки и применяет их.

- **`--policy`** — что происходит с входящим трафиком, который не разрешён ни одним правилом.
- **`--icmp`** — отвечать на ping. ICMP-ошибки и neighbour discovery
  пропускаются всегда.
- **`--ipv6`** — фильтровать IPv6 теми же правилами; `false` не трогает IPv6.
- **`--protect-docker`** — закрыть порты, которые публикует Docker, пока их не
  откроет правило со scope `docker` или `both` (или аллоулист).
- **`--disable-preset ssh|api|web`**, **`--enable-preset`** — выключить или
  включить выводимое правило. Для выключения `ssh` или `api` нужен
  **`--force`**: можно отрезать себе доступ.

### render

```
asc firewall render
```

Печатает таблицу, которую загрузило бы следующее применение.

### apply

```
asc firewall apply [--timeout <секунды>] [--no-rollback] [--force] [--no-wait]
```

Загружает сохранённые правила (после правок с `--no-apply`). Флаги — как у
`enable`.

### confirm

```
asc firewall confirm
```

Подтверждает ожидающее изменение. Новый ruleset становится тем, который
загружается при старте системы.

### rollback

```
asc firewall rollback
```

Откатывает ожидающее изменение прямо сейчас.

### ruleset show

```
asc firewall ruleset show [--raw]
```

Печатает весь ruleset так, как он в ядре (`nft list ruleset`), или с
**`--raw`** — текст, применённый в режиме RAW.

### ruleset edit

```
asc firewall ruleset edit --i-understand-the-risk [--timeout <секунды>] [--no-wait]
```

Правит весь ruleset в `$VISUAL`/`$EDITOR` и применяет его (режим RAW). Это
заменяет **все** таблицы, включая Docker и fail2ban, и может отрезать вам
доступ — поэтому флаг обязателен. Результат сначала проверяется `nft -c` и
применяется с тем же автоматическим откатом.

### ruleset apply

```
asc firewall ruleset apply <файл|-> --i-understand-the-risk [--timeout <секунды>] [--no-wait]
```

Заменяет весь ruleset содержимым файла (`-` читает stdin). Те же
предупреждения и откат, что у `ruleset edit`.

### tables

```
asc firewall tables
```

Печатает все таблицы nftables хоста, только для чтения, с владельцем (демон,
fail2ban, iptables или кто-то ещё).
